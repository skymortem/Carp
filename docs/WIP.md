```bash

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# тесты

# миграции

```

## Грабли, на которые уже наступали

- **Один процесс Uvicorn.** Планировщик и кеш сессии StarLine живут в процессе: с `--workers 2`
  будет двойной сбор и гонки.
- **`WorkingDirectory` = `backend`.** `DATABASE_URL` и `.env` — относительные пути; `/setup`
  пишет в `.env`, каталог должен быть записываемым.
- **`STARLINE_*` не задавать в systemd** — переменные окружения приоритетнее `.env`,
  и `/setup` перестанет влиять на сбор.
- **`create_all()` и миграции расходятся.** Тесты строят схему через `create_all`, поэтому
  новые миграции обязаны проверять существование колонок/таблиц, иначе падают на дубликате.
  Сверка: `alembic check`.
- **SQLite хранит `ts` без таймзоны.** Сравнения — наивный UTC; наружу отдаём ISO с `+00:00`,
  иначе браузер посчитает возраст со сдвигом.
- **Погода — внешняя зависимость.** `services/weather.py` ходит в Open-Meteo с таймаутом 4 с;
  любая ошибка → `outside_temp = null`, сбор не падает.
- **Консоль — только чтение.** Команды StarLine (`set_param`, `async`, `controls`) не проходят
  и до API не доходят; это проверено тестом.
